## 为什么旧 AV1 比 TSOG 大

上轮旧 AV1 为 367.58 MB、55.20 dB；TSOG 为 19.59 MB、48.99 dB，二者并不在同一画质点。

1. 每帧独立 Morton 排序破坏像素槽与高斯点的时序对应。仅第 0→1 帧，67.96% 的槽位换了点，58.35% 的属性码改变；固定同一 Morton 顺序后只有 3.00% 的码改变。
2. 将 45 个高阶 SH 分量逐点展开，占 59 个有效属性的 76.27%；每个点用 90 字节保存高阶 SH。三个 GOP 实际只有 1870/1848/1831 种量化 SH 向量，可改为两字节索引加一次性精确码本。上轮 TSOG 的 SH 码本与索引总共仅约 1.04 MB。
3. 颜色、SH、透明度和缩放在一个 GOP 内不变。每组还有约 6.7 万个位置与旋转均静止的点。旧方案仍然每帧铺满全部属性，依赖视频编码器自行发现这些高维重复。
4. 全部属性一律 16 位、高低字节分别铺平，产生大量难以预测的低位字节；TSOG 对旋转、缩放、DC、alpha 等使用更紧凑的量化表示。因此体积差距主要来自编码器之前的数据表示，而非 AV1 与 WebP 的名称。

这些结论由本地输入、码流和源码测量得出；分析原始数据见 `av1_structure_analysis.json`。

## 本次优化及画质保证

- 保持旧方案同一个全序列 min/max、同一套 16-bit 量化公式，未降低 SH 阶数，未删点，也未降低属性位数。
- 按不可变属性变化划分 GOP；每组只在关键帧做一次 Morton 排序，组内复用点序。
- SH 用精确唯一向量码本，避免有损聚类；不变属性与静态几何每组只存一次。
- 视频仅编码动态点的位置与四元数：相对前一帧做模 65536 的有符号差分、zigzag，再拆高低字节。
- 灰度视频 atlas 从 3852×3210 缩至 756×756。仍然一个视频帧对应一个 PLY 时间戳，解码时用关键帧数据补全整个高斯场景。
- 静态关键帧与码本为 NPZ+单线程 LZMA2，利用跨 GOP 的重复；运动仍为无损 AV1/MKV。报告体积包含视频、关键帧和全部播放必需元数据，不是只统计更小的视频。
- 对视频 atlas 和重建后完整 59 属性量化码表分别逐帧 SHA-256 校验；全部 60 帧通过，证明没有引入新的属性量化损失。
- 实测从 368.06 MB 降至 16.07 MB，减少 95.63%（22.90 倍）；PSNR 从 55.1979 到 55.1974 dB。
- 恢复原始行序与旧方案每帧 Morton 行序可能影响深度完全相同的点的栅格排序；是否影响图像以这次四视角 PSNR 为准，而不是只凭量化码一致推断。

## SMV

`smv-codec` 已迁入 `third_party/smv-codec` 并修复引用。这是本地编写的 SMV 载荷编码原型，不是新下载的上游项目；按用户目录组织要求一并放置。
SMV 使用 NPZ 关键帧、8-bit SH/DC/opacity/rotation 量化、16-bit 缩放、HEVC 无损运动视频。其显式、无淡入淡出的 GOP 时间线是扩展，原网页不能直接按原样播放该包。本次实际解码后以同一栅格器计算四视角 PSNR，不能用原网站格式兼容性代替画质验证。

## 测量规则

- 同一个 Python 3.12 压缩环境，方法串行；NumPy/BLAS/OpenMP、视频编解码、图像滤镜均限制一个工作线程。GSD 为一个工作进程；TSOG 的后台线程池替换为同步执行器，未并行生成图片。
- libaom-av1 使用 cpu-used=8、CRF0、gray、threads=1、row-mt=0；SMV x265 禁用线程池，使用一个帧线程。
- 编码包含读 PLY、分析、排序、量化、码本、压缩及写文件；解码包含读压缩文件、重建及标准 PLY 写入。外层进程启动、适配层导入和 GPU 渲染不计入，函数内按需导入计入。
- 每种方法 60 帧×4 视角共 240 张图，1222×684，黑背景，三阶 SH 栅格器，关闭抗锯齿。GSD v2 本身只保留 SH0；其余方案保留 SH3。
- 使用源相机和右移 0.2、左移 0.2、上移 0.15 场景单位的三个固定相机；参数与上轮相同，见 cameras.json。
- PSNR 为浮点 RGB 裁剪 [0,1] 后的全图、全部通道平均 MSE，再取 -10log10；PNG/MP4 仅供预览，不参与数值计算。
- 单次实测，未清空 OS 缓存；不是重复试验的统计均值。数据来自 SMV 解码后序列，组内静态/外观冗余较强，不能据此保证所有独立重建 PLY 都有同样收益。
- 旧四线程结果完整保留在 benchmark/results；本表所有时间均来自新的一线程实测，未混用旧时间。
- 编码参数参考 [FFmpeg 官方文档](https://ffmpeg.org/ffmpeg-codecs.html#libaom_002dav1)。

逐图指标见各方案 quality.json；CSV、时间日志、解码 PLY、量化校验、视频和预览均在本报告同目录。
